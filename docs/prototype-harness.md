# Milestone 3 harness contract

The Rust package under `prototypes/aether-poc/` consumes the accepted M2 invented bundle. It calls the existing complete construction checker before exposing fixtures, parses a strict typed manifest, checks confined paths and selects one endpoint artifact. Inputs are named fixture variants, never live serving endpoints. The supported manifest is repository-relative `fixtures/prototype/manifest.json`; callers supply a repository root. Listing preserves all twelve groups, 36 variants, source/requirement/association references and artifact roles, including variants without an endpoint and declared malformed endpoint cases.

`fixture::EndpointInput` contains private validated endpoint bytes, bundle/variant/manifest identities and the indexed byte hash. Public callers can inspect bytes but cannot construct a forged input or attach oracle assertions. Construction checking may inspect independently authored expected files. The transport scenario receives only the endpoint input; it never copies a semantic oracle into an actual result. Artifact reads are bounded to the declared size and at most 1 MiB and recheck SHA-256 at selection. The manifest is bounded before allocation. Absolute/traversal paths and symlink components are rejected; a repository under concurrent hostile mutation is outside the local harness boundary. These checks are not a production secure acquisition design.

`endpoint::FixtureServer` owns its listener, worker and shutdown flag. It binds only numeric 127.0.0.1, defaults to an ephemeral port, serves one selected artifact and never accepts a URL/path that selects another file. Its local client connects only to this owned server. The server accepts at most 16 connections within at most 30 seconds (defaults one/five seconds), with absolute one-second peer I/O deadlines, 8 KiB headers and bounded bodies. All accepted connections count, including partial/malformed peers. Interrupted/failed scenarios shut down and join the worker; dropping a server also joins it. Scheduling and OS timeout rounding can add small delay; this is bounded local cleanup behavior, not a real-time guarantee.

The HTTP subset is GET /metrics over HTTP/1.1 with Host, Content-Length, connection close and no body/chunking/upgrade. Unknown paths return 404, other methods 405, malformed or unsupported headers 400 and oversized headers 431. The original payload, including intentionally malformed metric text, returns 200 unchanged. Rejected ordinary small request bodies are discarded in a bounded manner after sending a closing response; arbitrarily large hostile requests can be closed with a TCP reset. Partial peers are closed at deadline and reported in bounded peer-error lists. Client responses must have status 200, finite bounded exact Content-Length and close; redirects, unsupported framing, truncated and excess bodies fail. It is not a general HTTP server/client library.

`endpoint-roundtrip` performs a real local request, waits for server termination and compares received bytes/hash/length against indexed input. Its JSON report is stable: no ephemeral port, wall timestamp, elapsed duration or random path. It reports transport/harness passed only after the comparison; semantic execution stays not_run, readiness false and production support false. Standalone serving uses separate startup/shutdown events and lists peer errors; it does not imply each request was valid. All errors have a stable code/context and optional fixture identity. Future metric/query/collection scenarios fail explicitly as not_prototyped.

Future observation records should preserve native family name, declared type, original labels, publisher identity and optional measured-subject identity. A publisher is where the metric is exported; its subject can be a remote worker or a multi-device replica. A virtual interval needs start/end, unit, clock domain and uncertainty; supplying microsecond integers does not measure physical microsecond accuracy. A quality state must distinguish justified values from missing, unavailable and ambiguous evidence. M3 documents these shapes; it does not emit parsed observations.

Future metadata links should name the two scoped entities/incarnations, relationship type, evidence references, valid-from/valid-until interval and quality state. An incarnation identifies one lifetime of a reused ID. Unknown/ambiguous ownership must remain explicit; publisher locality, model name, PID or device ordinal alone does not prove membership. These are M4/M5 handoff requirements, not implemented joins or finalized production interfaces.

No accepted requirements, research routes, M1/M2 ledgers or proposed budgets are advanced by harness success. All twelve PX experiments, deployed schemas/capabilities, physical timing, overhead and production durability remain unverified. M4 will implement native metric parsing and justified calculations; M5 identity joins; M6 storage/query/recovery; M7 replay/correlation; M8 the combined demonstration.

## Milestone 4 extension

The original byte-roundtrip command retains its transport-only semantics and not_run semantic field. The package now also implements seven named metric functions plus independent scenario/milestone verification. These produce separate current functional-execution reports and a new ledger; they do not alter historical M1/M2 planning states or budget agreements. Native parsing uses the owned local HTTP exchange; rates and other calculations use supplied typed synthetic records. See [metric semantics](prototype-metric-semantics.md) for exact stage/variant accounting, finite grammar, privacy projection, unknown states and source limitations. Query, collection, event replay, relationship resolution and storage remain later-stage work.

## Milestone 5 extension

The package now also implements five synthetic enrichment adapters and seven additive boundary cases. Scoped identity, explicit evidence/validity and immutable set-valued relationships keep PID reuse and resource membership from relabeling or duplicating measurements. Untimed links and unresolved physical/transport identity stay qualified. The original M4 output/ledger is preserved; current association evidence and all 58 association facets are tracked separately. See [enrichment contract](prototype-enrichment-contract.md). No real discovery or production identity service is implemented.
