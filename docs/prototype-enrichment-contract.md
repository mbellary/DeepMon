# Synthetic enrichment contract — Milestone 5

Aether's Rust prototype now evaluates explicit metadata relationships without discovering real hosts, processes, devices or serving workloads. All input values are invented. The original 250 metric requirements, 58 associations, source mappings, twelve PX specifications, original fixtures/budgets and historical M4 ledger remain unchanged. This contract defines a local functional experiment; production architecture and real-source compatibility remain unscoped/unverified.

## Identity and evidence

`identity::EntityKey` contains a fixture correlation scope, kind, opaque locator, incarnation and optional evidenced host/boot/namespace fields. These optional fields participate in identity equality; absent fields are not guessed. Strings such as host-boot/PID17 and fixture-netns/ifindex7 are opaque symbolic locators, not parsed host or namespace facts. The correlation scope based on fixture identity isolates invented records; it is not a discovered host namespace.

`EntityRef` distinguishes fully keyed entities, explicitly symbolic references and unknown identity. A declared container/GPU string can be retained without inventing its UUID, physical host, partition or container lifetime. `IdentityGraph` stores immutable historical nodes/relationships and explicit evidence. Fully keyed targets must exist; explicitly symbolic references remain unverified. The graph allows up to 32 distinct nodes and 32 relationships. Identical repeated evidence is idempotent; reusing an evidence ID for changed content is an error, not last-write-wins. Raw merge batches are bounded, and extension inputs remain limited to 64 metadata records per case/update.

Resolution uses explicit identity and relationship type. A unique time-valid mapping can be resolved; multiple distinct single-owner candidates stay ambiguous; incomplete membership stays partial. Supplied untimed candidates/sets remain reported with temporal_status=unspecified_input. Permission denial is not proof of absence. Resolved here means a justified mapping within invented evidence, not a physically verified production identity. Outputs retain physical_identity_status=unverified_synthetic.

Validity uses half-open [start,end) intervals. Ending at 10 excludes time 10. A full observation/query interval must be covered by one relationship and the relevant entity lifetimes. Cross-incarnation intervals, incompatible/uncertain clocks or missing validity cannot produce an exact timed association. No wall-clock fallback, current-owner lookup or invented link interval is used. Original bounded metadata timestamps use the envelope's one explicit microsecond clock as a documented fixture-adapter binding; absent/multiple unmatched clocks cannot select an implicit default. Additional cases supply their own query times explicitly. Query times are synthetic requests, not retroactively fabricated capture timestamps on original telemetry.

Enrichment returns one observation with the unchanged original measurement and set-valued relationship references. It does not expand values per GPU/NIC or merge raw producer populations. A query must identify a keyed emitter or subject already present in the measurement; arbitrary other subjects cannot be attached. Association results retain their queried source key. Allocated resources and observed participants remain separate. Historical enriched values are immutable when new evidence is merged.

## Separate boundary bundle

`fixtures/enrichment-v1/manifest.json` pins the original bundle, association definitions and registry hashes. Seven input/expected pairs plus README/manifest produce sixteen files. Paths, roles, media types, sizes, SHA-256, strict schemas, case IDs and the indexed tree are checked. Each artifact is at most 1 MiB; inputs allow 32 nodes/32 relationships, 64 measurements/queries and 256-byte strings/labels. Symlinks, traversal, absolute paths, extra files, duplicate cases and drifted baseline hashes fail. These are local test limits, not agreed runtime budgets.

E5-01 tests PID/container queries at 5/10/15/20 microseconds and an interval crossing a lifetime boundary. E5-02 tests zero/one/two candidates and input-order independence. E5-03 tests explicit boot/namespace separation and missing incarnation. E5-04 retains one count 100 with a heterogeneous allocated set, another replica and unknown participation. E5-05 tests time-varying membership and unchanged historical output. E5-06 separates NIC scope, capability, preference, control protocol and absent operation/library evidence. E5-07 tests denial with known process context, safe output, identical replay and explicit update conflict.

Literal expectations are authored by the Rust enrichment-data helper without resolver calls. Run/verify are separate. The seven cases currently contain 69 checked expectations/invariants, including exact query-set coverage, measurement identity/value/cardinality, native/emitter/subject/scope preservation, immutable history, permutation invariance and expected update failure. Extension counts never increase the original 49-assertion total. A reported negative update is data in the run result; verification passes only if the actual failure matches its independently authored expectation.

## Execution tracking and privacy

`docs/prototype-enrichment-execution-status.json` records current M5 results, seven new original matches and ten rechecks. Prior-only assertions link the preserved M4 ledger and are explicitly not rerun by the M5 summary. The combined unique original view is 31 matched functional assertions, two M4 expected parser rejections, one M4 proof, one PX12 queue deferral and 14 later-stage PX08/PX09/PX10 assertions not run: 49 in total. This is stage accounting, not a product-support percentage or whole-PX runtime pass.

`docs/prototype-enrichment-coverage.json` retains every original M01–M58 definition and records specific exercised facets separately from untested associations/remainders. Physical/partition/process-GPU-use inventory without direct tests stays unexercised; carrying a generic unknown identity is not complete association evidence. Model/library/driver claims stay qualified. All entries retain real verification not_run and readiness false.

The graph performs no host/runtime/device reads. Original metadata values are transient inputs; exported reports use the safe projection and synthetic-marker sanitation boundary. Serialization errors and comparison diagnostics do not echo raw sensitive fields. Original invented input/source archives retain their exact bytes as historical test material, separate from customer-output artifacts.

The Rust fixture/evidence helpers protect differing existing output and allow identical reruns. The M5 summary imports prior results only when the M4 ledger hash matches its accepted artifact index. Report/input/oracle/result hashes and explicit provenance are retained. Evidence indexes are not signed execution attestations. Budget agreements remain unset, px_runtime_acceptance_status=blocked_unagreed_budget, real_verification=not_run and production_support_claimed=false. No overhead, real-source feasibility, backward compatibility or production durability guarantee follows.
