# Step 3: metric-to-source coverage matrix

Research date: 1 November 2026.

## Purpose and scope

Map every one of the **250 original metric-family IDs** to a documented or explicitly conditional collection route for Aether. The software reviewed first is **vLLM, SGLang and NVIDIA Dynamo**. This is a research starting point, not an exclusive product-support list. All 250 requirements remain in scope. The [native baseline](engine-native-metrics-baseline.md) supplies existing endpoint evidence, and the [metadata matrix](metadata-enrichment-matrix.md) supplies the M01–M58 identity/association definitions. The original [requirements catalog](aether-metrics-catalog.md) remains unchanged.

No source process, workload or device was inspected. No adapters, collectors, probes or integrations have been implemented or performance-tested by this step. No release, hardware, kernel, permission policy, SLO threshold or sampling interval is assumed. Every row is **documentation/design evidence**, not certified deployment support.

The original catalog contains TGI/Triton/TensorRT-LLM-specific measurements. Their own documented sources are eligible without an equivalent in vLLM, SGLang or Dynamo. The scope-error recheck restores those routes while preserving source boundaries. The native baseline remains a review of the first three engines, not a complete inventory for every source.

The [source-mapping recheck](source-mapping-recheck.md) is complete at the documentation level: 25 of the 26 formerly U rows now have E routes; L1-001 retains a counting-boundary gap. Four nearby R rows also have direct E routes. These classifications do not establish deployed support or complete attribution.

The [versioned evidence baseline](validation-evidence-baseline.md) now pins source inputs and records all 26 historical U outcomes. The first validation environment is local and synthetic because no existing cluster is available. Deployed schema and capability checks remain `not_run`; no route classification changed.

## Classification

- **E**: Existing endpoint: documented in-scope source route; feature/schema/scope still require deployment verification.
- **R**: Derived: calculation over named inputs. Input acquisition and missing evidence are separate dependencies; this is not an availability claim.
- **H**: Host/device/fabric collector: collection outside core engine endpoints, including an external switch integration where specified.
- **I**: Application/library/device tracing integration: semantic records or profiling beyond established core endpoints; may require workload configuration or process instrumentation.
- **U**: Unresolved mapping: the source or its measurement meaning still needs review. A source is not excluded because its engine has not yet been reviewed.

Routes are not a maturity score or priority. R can depend on I or U, so a derived row may be blocked. H includes external switch sources, explicitly flagged as not host-only. U means insufficient evidence for an exact reviewed-source mapping, not proof that new instrumentation is necessary. I is a proposed acquisition class; it does not establish that an appropriate interface already exists.

**An endpoint route does not establish the full original scope.** A native engine-level TTFT histogram can be collected while its replica mapping remains unknown. The required-scope and M-ID columns capture that distinction. Resource-only host metrics can be useful without workload attribution; they must retain the narrower observed scope.

## Source selection and semantics

- Existing endpoint mappings come from the native baseline and the additional primary sources checked in the source-mapping recheck. Per-row review references are recorded in the structured companion.
- Dynamo frontend, router, component and backend-engine observations remain separate producers and timing/counting boundaries. Backend pass-through is not an additional independent measurement of the same logical output.
- A grouped requirement can contain components with different support. A row explicitly marked partial must not be reported as complete coverage.
- Configured capacities, current request populations and actual per-iteration sequence counts are distinct. Device framebuffer usage is not engine-allocator memory usage.
- A native success-like family name can contain multiple finish reasons. Successful/failed terminal populations require policy and completeness checks.
- Exact SLO compliance requires a compatible histogram boundary or suitable raw observations. Goodput and exact variance generally need joint per-request data or sufficient moments; marginal buckets cannot supply those facts.
- Counter family names and wire `_total` samples must be resolved through HELP/TYPE. Existing histograms do not supply original events, kernel timelines or arbitrary per-request dimensions.
- Numeric cadence and overhead are unset for every route. Source freshness, event resolution, clock uncertainty, agent polling, upload batching and query freshness remain separate.

## Shared collection prerequisites

| Profile | Requirements |
|---|---|
| endpoint | Read an already exposed/reachable endpoint; inspect exact release, HELP/TYPE, labels and buckets. Do not enable metrics or change workload configuration automatically. |
| derived | Validate input units, populations, time windows and identities; handle resets and membership changes. All input acquisition/configuration restrictions remain in force. |
| gpu | Supported NVIDIA driver and NVML/DCGM access; per-device/partition field capability and freshness checks. GPU profiling counters may require elevated permissions and conflict with other tools. |
| host | Read access to the actual host/namespace procfs/sysfs and relevant accounting interfaces; verify kernel/configuration, process lifetime and source units. |
| cgroup | Verified cgroup version/hierarchy and read access. The named catalog interfaces are cgroup v2; no v1 fallback implementation is assumed. |
| bpf | Supported collector-specific attachment points (scheduler tracepoints or validated uprobes) and BPF/perf/tracing permissions; validated attachment and event-loss accounting. No application code change is intended; host authorization/capability is still required. |
| rdma | Supported RDMA/NIC driver, device/port counter exposure and read access. Verify native units, reset/saturation behavior and per-port link mode; workload attribution is a separate join. |
| net | Read relevant network-namespace interface/protocol statistics; distinguish virtual/physical layers and aggregate/detail counters. TCP sources do not measure RDMA payload traffic. |
| switch | External vendor/controller interface and read credentials; no specific switch API, counter schema or cadence is established. Host-only completeness is not claimed. |
| trace | Compatible existing trace output or supported instrumentation path. Generating records may need plugin loading, process injection, configuration/restart and profiling permission. Strict host-only coverage is not established. |
| semantic | Explicit existing semantic records or a new supported integration. Required event IDs, boundaries, population and completeness must be established before reporting the metric. |
| unresolved | Keep the original requirement and source. Review relevant TGI, Triton, TensorRT-LLM and other sources; do not require an equivalent in the three engines reviewed first. |

Each row additionally inherits its original source limitations. Driver/library references are scoped to supported NVIDIA implementations where named; they do not imply equivalent coverage on other accelerator vendors.

## Dependency and zero-application-change interpretation

| Path | What can be claimed at this stage | What cannot be claimed |
|---|---|---|
| Existing exposed endpoint → E | Aether can be designed to read it externally | That the endpoint/optional family is enabled, accessible or fully attributed in every deployment |
| Existing inputs → R | The stated formula identifies required inputs | That inputs exist, joint data can be reconstructed, or unknown policy values can be assumed |
| Host interfaces → H | A host-side source route is identified | That source permissions, field support, overhead and workload attribution are already validated |
| External switch interface → H | Separate fabric integration is explicitly required | Universal zero-integration fabric coverage |
| Semantic/profiling records → I | Required record semantics and deployment risks are identified | That source-code-free injection is the same as strictly host-only observation |
| Source mapping not yet verified → U | The source exists, but evidence does not yet establish the required counting boundary | That the metric is impossible or that the customer must adopt another engine |

A pre-existing profiler/log stream can sometimes be read without changing a workload. Automatically enabling that stream, changing environment variables, loading a plugin, injecting a library, restarting an engine or enabling optional metric families is not authorized by this document. Those choices belong in the next collection contract.
